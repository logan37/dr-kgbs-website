# Keep the stack, prerender it, move hosting

Dr. Srinija Kummaraganti's site does not need a new template or a new framework. The fastest sound path is to keep React 19, Vite, Tailwind and shadcn/ui, convert the single catch-all route into React Router framework mode with `ssr: false` and a `prerender` list so each of the roughly 22 planned pages ships as its own HTML file, and move hosting from the GitHub Pages subpath to Cloudflare Workers static assets on a custom domain. Booking at launch should be a short request form sent through a free form service, a `wa.me` WhatsApp link to the clinic's WhatsApp Business app, and tap-to-call, with staff confirming by hand. A clinic platform such as Eka Care can replace the form later without touching the site's structure. The larger risk is regulatory. On 6 October 2026 the National Medical Commission issued advertising guidelines that bar testimonials, review solicitation, superlatives and patient counts on doctors' websites, and the current codebase still contains a `TestimonialsSection`. That section, and any "best pulmonologist" wording, has to go before launch. Privacy obligations under the DPDP Rules 2025 take full effect on 13 May 2027 (a proposal to bring this forward was not confirmed as notified), so the appointment form should carry a proper consent notice from day one.

## No ready-made template matches a single Hyderabad specialist

No free template was found that uses Vite, React, Tailwind and shadcn/ui for a single-doctor practice. The closest code is **Linden Health**, an MIT-licensed Next.js 16 project on Tailwind 4 and shadcn/ui, which includes a marketing site, doctor profiles, a five-step booking UI, a patient portal and staff admin ([GitHub](https://github.com/jknithin36/linden-health)). It had 5 commits and 0 stars when checked, and most of it (portal, auth, admin) is irrelevant here. Its hero, doctor card, services grid and booking-step components can be copied into the Vite app by swapping `next/link` and `next/image` for plain equivalents. **Viva Medical**, a free Astro 7 and Tailwind v4 theme with seven static pages and reusable hero, card, CTA and FAQ components, is a useful layout reference ([Astro themes](https://astro.build/themes/details/viva-medical-healthcare-astro-theme/)). The Opencals "Clarity" template is MIT-licensed but its booking runs on the Opencals API and Stripe; what is worth taking from it is the pattern of keeping all copy in one `site-config.ts` file and emitting `MedicalClinic` structured data, a sitemap and robots.txt ([Opencals blog](https://opencals.com/blog/templates/clarity)). Templates to skip include the themixlyweb ENT template, which is Bootstrap and SCSS with doctor pages behind a paywall and conflicting licence terms ([GitHub](https://github.com/themixlyweb/nextjs-medical-website-template)), and Doccure on ThemeForest, a Bootstrap React template that a buyer says has no backend ([ThemeForest](https://themeforest.net/comments/29657303)). Framer, Webflow, Wix and Squarespace all have clinic templates, but none is built around Indian patterns such as WhatsApp booking or INR fees, and none gives code ownership.

The best guide to page structure comes from local competitors. **drnalininagalla.com**, a single pulmonologist and sleep specialist in Narsingi and Gachibowli, uses a credentials-led hero, services grouped into pulmonary and sleep, locally targeted blog posts such as "COPD in Hyderabad", a sleep quiz, and two clinic timetables with map links ([drnalininagalla.com](https://drnalininagalla.com/)). It shows no schema markup and gives inconsistent experience figures ("24+" and "over 20" years). **Respire Airway Clinics**, which recently opened a Kondapur location, has deep condition sub-pages for asthma, COPD, chronic cough, allergic rhinitis, sleep apnea and a "sleep study cost" page, and mentions WhatsApp booking ([respireairwayclinics.com](https://respireairwayclinics.com/)). Neither site shows fees, language options or JSON-LD, and those are the openings for this site. Fees in Hyderabad usually appear only on Practo; one local pulmonologist and allergist listing shows ₹600 ([Practo](https://www.practo.com/hyderabad/clinic/respicare-allergy-asthma-snoring-centre-as-rao-nagar)). Practo offers no current booking embed; the only widget found is a WordPress plugin tested up to WordPress 4.5 ([readme](https://cdn.jsdelivr.net/wp/practo/trunk/readme.txt)), so a plain link to a Practo profile is the most the site should carry. Testimonials sections, which both competitors use, are now prohibited (see the compliance section below).

## React Router prerendering fixes the SEO gap with the least rewrite

The site today is one `BrowserRouter` route rendering every section on a single page, so crawlers get one URL and one title. The SEO plan in `docs/seo/SITE-STRUCTURE.md` already calls for about 22 separate pages (eight conditions, six tests, visit, about, privacy and others) served as static HTML. Three serious ways exist to get there.

| Option | What it takes | Main trade-off |
|---|---|---|
| React Router framework mode, `ssr: false` + `prerender` | 1 to 3 developer days (estimate) | Every page still hydrates the React runtime |
| Astro 6 with React islands | 3 to 6 developer days (estimate) | Rewrites layouts in `.astro`; least JavaScript shipped |
| Next.js `output: 'export'` | Rewrite to App Router conventions | Loses `next/image` optimisation, redirects and headers |

React Router's prerendering works only in framework mode. Setting `ssr: false` with a `prerender` array produces an HTML file per path plus a `.data` file for client-side navigation, and needs no runtime server ([React Router docs](https://reactrouter.com/how-to/pre-rendering)). The constraint that matters here is that route `action` exports are prohibited under `ssr: false`, so the booking form must post to an external endpoint. React Router lists **8.5.1 as the current release**, while the project's `package.json` pins `react-router` ^7.6.1, so the conversion is the moment to move to v8, after checking the v8 docs for any change to the prerender API. The older add-ons are out: vite-react-ssg says it will maintain SSG only for React Router v6 users, recommends React Router's built-in SSG instead, and has not ticked off React 19 support ([GitHub](https://github.com/Daydreamer-riri/vite-react-ssg)). react-snap is described as unmaintained ([DEV Community](https://dev.to/vijay_rathod_b9db92cb65f8/pre-rendering-a-160-post-react-spa-with-react-snap-the-gotcha-that-silently-breaks-your-seo-3ino)). Vike works but means adopting a second framework's conventions, and its React adapter is still pre-1.0 ([npm](https://www.npmjs.com/package/vike-react)).

Astro is the stronger long-term fit for a content site. Astro 6, released on **10 March 2026**, runs on Vite 7, ships zero JavaScript by default, and adds a built-in Fonts API that self-hosts and preloads fonts ([Astro blog](https://astro.build/blog/astro-6)). Its Markdown content collections with a typed frontmatter schema would suit condition pages that need `reviewedBy` and `lastReviewed` fields. The case against moving now is cost and timing: the existing sections, the lung-health screener and the shadcn components all work, and a static site of 22 pages hydrating React will still meet the Core Web Vitals thresholds of **LCP under 2.5 s, INP under 200 ms and CLS under 0.1** at the 75th percentile ([web.dev](https://web.dev/articles/vitals)) if images and fonts are handled carefully. No benchmark comparing Astro and React Router prerender on similar sites was found, so the performance gap is an expectation, not a measured number. If the articles section grows past a few dozen posts and the doctor wants to edit content herself, Astro with the Keystatic Git-based CMS, which has an admin at `/keystatic` and costs nothing ([Lucky Media](https://www.luckymedia.dev/compare/keystatic-vs-tina-cms)), is the migration to plan for. Until then, condition and test pages can live as Markdown or TypeScript content files in the repo, and the existing `src/content/types.ts` is a reasonable start for that.

## Cloudflare is the only free host that fits a commercial clinic

GitHub Pages caps sites at 1 GB with a soft bandwidth limit of 100 GB a month, has no serverless functions, and its terms say it is not meant as free hosting to "run your online business" ([GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)). It also cannot set cache or security headers, and the subpath forces a `basename` in the router. Vercel's Hobby plan is restricted to "non-commercial personal use only", so a medical practice would need Pro at **$20 per seat per month** ([Vercel](https://vercel.com/docs/plans/hobby)). Netlify's free plan is now a 300-credit allowance in which each production deploy costs 15 credits and bandwidth costs 20 credits per GB ([Netlify](https://www.netlify.com/pricing/)), which leaves room for roughly 20 deploys a month before any traffic.

Cloudflare serves static asset requests free and without a cap ([Cloudflare](https://developers.cloudflare.com/pages/functions/pricing/index.md)). The free Workers plan allows **100,000 requests a day**, enough for a booking endpoint, plus up to 100 `_headers` rules and 2,100 `_redirects` rules ([Cloudflare Docs](https://developers.cloudflare.com/workers/platform/limits/)). Cloudflare lists **22 edge cities in India, including Hyderabad**, Chennai and Mumbai ([Cloudflare network](https://www.cloudflare.com/network/)), which puts the server close to Kondapur patients on mobile data. Third-party sources say new projects should use Workers with static assets because Pages is now the legacy path ([DeployHQ](https://www.deployhq.com/blog/deployhq-static-hosting-vs-cloudflare-pages)). The setup is a custom domain with DNS on Cloudflare for free TLS, a `_headers` file that marks hashed assets as immutable, and redirects from the old GitHub Pages URLs. No comparable India location data or TTFB benchmark was found for Vercel or Netlify, so the latency advantage is likely but not measured.

## A form and WhatsApp cover booking until a clinic platform is needed

A single doctor seeing patients at a diagnostics centre needs a reliable way to receive requests more than she needs a slot engine. **Web3Forms** is free for 250 submissions a month ([Web3Forms](https://web3forms.com/pricing)). The form should be posted from the browser and kept to name, phone, preferred day and an optional short reason for visit. Next to it, a `wa.me` link with a prefilled message opens a chat with the clinic's free WhatsApp Business app, and a `tel:` link handles callers. The paid WhatsApp Business Platform charges per delivered template message, and since 1 October 2026 service messages are free only up to 1,000 per number per month ([Meta](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing.md)). Third-party sources put the Indian utility rate near ₹0.115 a message ([Free Press Journal](https://www.freepressjournal.in/tech/how-much-does-india-have-to-pay-for-whatsapp-messages-from-october-1)), so automated reminders are cheap in Meta fees, but they only make sense once volume justifies a provider subscription. If spam becomes a problem, a small Cloudflare Worker at `/api/booking` with a Turnstile check can replace Web3Forms, though it then needs an email-sending service whose free limits were not verified.

The next step, when manual confirmation becomes a burden, is an Indian clinic platform that issues a direct booking link. Eka Care's vendor page lists plans from **₹4,999 a year** with a "Personalised Booking Link (0% Commission)" and 1,200 credits for WhatsApp messages ([eka.care](https://www.eka.care/eka-for-doctors/emr-ehr-medical-software/cardiologists)); a third-party listing quotes higher prices, so confirm before buying. Practo Ray practice management is listed by resellers at ₹999 to ₹1,999 a month, and Practo does not publish its price ([Techjockey](https://www.techjockey.com/detail/practo-ray)). Practo's marketplace listings carry other costs: one urologist reported ₹350 to ₹450 connection fees per enquiry ([Medical Dialogues](https://medicaldialogues.in/news/health/doctors/urologist-slams-practo-for-unethical-charges-on-patient-inquiries-138562)), and the NMC guidelines now treat pay-per-lead arrangements as a violation. Because the site would only link to the booking page, changing vendor later means changing one URL. Generic schedulers such as Cal.com or Google Calendar's free booking page suit fixed teleconsult slots better than a walk-in OPD. A custom Supabase backend, available in a Mumbai region with a Pro plan from $25 a month ([Supabase](https://supabase.com/docs/guides/platform/regions)), would cost weeks of development for slot logic, an admin screen, reminders and consent records, and is only worth it for something no platform offers, such as booking a scan at TrueMed alongside a consultation. One open question decides a lot here: whether TrueMed Diagnostics already runs a booking or hospital management system the doctor could use. That should be asked before choosing anything in this stage.

ABDM registration (HFR for the facility, HPR for the doctor) is free and voluntary and enables ABHA-based "Scan and Share" OPD registration ([Digital Health News](https://www.digitalhealthnews.com/ayushman-bharat-digital-mission-abdm-for-small-clinics-independent-doctors)). It matters in the clinic, usually through an ABDM-compliant EMR, and the website gains nothing from it beyond an optional HPR ID.

## The October 2026 NMC guidelines decide what the site can say

The NMC's "Guidelines on Ethical Advertising and Public Communication" (Public Notice R-13014/01/2024-Ethics, 6 October 2026) took effect immediately and explicitly cover websites, blogs, WhatsApp, search-engine content and AI-generated material ([NMC notice](https://medicaldialogues.in/pdf_upload/2026/10/07/nmc-guidelines-on-ethical-advertising-and-public-communication-478642.pdf)). They are read alongside the IMC 2002 Professional Conduct Regulations, which remain in force because the NMC's 2023 regulations were put in abeyance ([Legality Simplified](https://legalitysimplified.com/?p=36875)). The Telangana Medical Council enforces them, with graded penalties that run from a warning and ethics training for a first violation to suspension of 3 to 6 months for a third, and 6 to 12 months for misleading cure claims or digital mass solicitation ([NMC notice](https://medicaldialogues.in/pdf_upload/2026/10/07/nmc-guidelines-on-ethical-advertising-and-public-communication-478642.pdf)). TGMC has already issued show-cause notices over social-media advertising by a Hyderabad hospital ([Medical Dialogues](https://medicaldialogues.in/news/health/hospital-diagnostics/violation-of-nmc-act-telangana-medical-council-show-cause-notice-to-hospital-for-colluding-with-unqualified-practitioners-140982)), and the Tamil Nadu council sent notices to about 100 practitioners over online and website ads ([Medical Dialogues](https://medicaldialogues.in/disciplinary-action-tn-medical-council-notices-to-100-medical-practitioners-for-online-website-advertisements)).

The guidelines require every electronic-media post to show the doctor's **name, qualifications, registration status and SMC or NMR registration number** (clause 3.2, Explanation III). Clause 8.1 prohibits testimonials from patients or anyone else, "best", "No.1", "leading" or "top" claims unless independently verifiable, success rates and numbers of patients treated, before-and-after images, discounts and "free first consultation" offers, referral or lead fees, and fear-based copy. Explanation V bars a doctor from requesting or sharing patient reviews for promotion, which is stricter than Google, whose policy allows asking for genuine reviews without incentives ([Google](https://support.google.com/contributionpolicy/answer/7400114)). Clause 9.1 treats a factual directory-style doctor profile with qualifications, specialty, registration and availability as patient information, and clauses 8.2 and 9.3 permit a factual declaration of fees. The IMC 2002 Regulations add that fees should be announced before service (1.8) and that only recognised degrees may follow the doctor's name (1.4.2) ([bare act](https://bnblegal.com/bareact/the-indian-medical-council-professional-conduct-etiquette-and-ethics-regulations-2002/)). The doctor's photograph is unsettled: clause 9.2 bars it only where it works as self-advertisement, so one small headshot on the About page is defensible, while a large hero portrait is the riskier choice. AI-generated images must carry a label saying so (clause 7.2).

Pulmonology carries one extra hazard. The Drugs and Magic Remedies Act 1954 is a criminal law that bars taking part in any advertisement suggesting a drug to treat scheduled diseases, and the schedule includes **tuberculosis, pneumonia and pleurisy**, with up to six months' imprisonment for a first conviction ([bare act](https://www.legalauthority.in/bare-act/drugs-and-magic-remedies-1954)). The planned tuberculosis and pleural effusion pages should explain symptoms, tests and the general course of care, name no drug brands, and avoid any cure promise.

For the appointment form, the DPDP Rules 2025 were notified in November 2025 and the core duties (notice, consent, security, breach reporting, erasure) start on **13 May 2027** ([India Briefing](https://www.india-briefing.com/news/dpdp-rules-2025-india-data-protection-law-compliance-40769.html/)). MeitY consulted on shortening this to 12 months, which would mean November 2026, but no amendment was found ([Storyboard18](https://www.storyboard18.com/amp/digital/meity-seeks-industry-views-on-fast-tracking-dpdp-act-rollout-proposes-12-month-compliance-timeline-88332.htm)), so the safe assumption is that the rules apply now. The form needs a plain-language notice listing what is collected, why, which processors receive it (the form service and Meta for WhatsApp), how to withdraw consent or ask for deletion, and a contact for complaints. Consent must be an unticked checkbox. Breaches must be reported to the Data Protection Board with a detailed report within 72 hours, and penalties reach ₹250 crore with no small-business exemption ([India Briefing](https://www.india-briefing.com/news/dpdp-rules-2025-india-data-protection-law-compliance-40769.html/)).

## The recommended plan

| Step | Work | Cost |
|---|---|---|
| 1. Compliance pass | Delete `TestimonialsSection`; remove superlatives, patient counts and any review prompts from copy, titles and meta tags; add name, recognised degrees and Telangana Medical Council registration number to the header or footer; add a factual fee line; decide on the photo | Content time only |
| 2. Prerender | Move to React Router v8 framework mode with `ssr: false` and a `prerender` list for the ~22 pages in `SITE-STRUCTURE.md`; per-route `meta` for title, description and canonical; `Physician` and `MedicalClinic` JSON-LD; sitemap | 1 to 3 developer days (estimate) |
| 3. Borrow components | Port hero, doctor card, services grid and FAQ patterns from Linden Health (MIT); keep one `site-config.ts` for name, address, hours, fees and phone | 1 to 2 days (estimate) |
| 4. Host | Cloudflare Workers static assets on a custom domain; `_headers` for caching; redirects from the GitHub Pages URLs | Free tier, domain fee only |
| 5. Booking | Web3Forms request form with DPDP notice and consent checkbox; `wa.me` and `tel:` buttons; privacy and medical-disclaimer pages | Free up to 250 requests a month |
| 6. Later | Eka Care or a similar 0%-commission booking link once volume grows; consider Astro plus Keystatic if the doctor wants to edit articles herself | From ₹4,999 a year |

Images should be built as AVIF or WebP with explicit width and height, and the Google Maps embed should load only on click so it does not cause layout shift. Analytics should be Cloudflare Web Analytics or similar rather than a heavy tag. The Google Business Profile should hold factual fields only and link to the site, with no review-request campaign and no paid ads promoting the doctor, since the NMC guidelines count sponsored and search-engine promotion as advertising.

## Conclusion

The technical choices here are easy and reversible: prerendering and a host change take under a week and cost almost nothing, and a booking link can be swapped at any time. The content choices carry the risk. The two strongest local competitors both run testimonial sections and credential-heavy promotional heroes that the October 2026 guidelines now prohibit, so a site that is plainly factual, shows the registration number, publishes fees and explains tests clearly is both the compliant option and one that stands out in the Kondapur and Hitec City search results. Several facts in this plan were not confirmed and should be checked before launch: the React Router v8 prerender API, Eka Care's current pricing, whether TrueMed already has a booking system, TGMC's preferred registration-number format, and whether MeitY has shortened the DPDP deadline. None of these is legal advice; a short review of the final copy by someone familiar with TGMC practice would be worth the cost.
